# 演示与录制脚本

实际演示视频尚未录制，不能由软件模拟代替。先完成 [验收](acceptance.md)，再用已验收的commit录制；提示词按 [分阶段提示词](agent-prompt.md) 选择。

## 建议三分钟主线

| 时段 | 画面与操作 | 要证明的事情 |
| --- | --- | --- |
| 0:00–0:20 | 小车、独立确认按钮、承接箱；一句话介绍用户场景 | 产品解决什么问题，不铺陈未实现能力 |
| 0:20–0:55 | “查询状态”“以40%速度前进500毫秒”“停止” | 自然语言到真实MCP参数和输出，停止能覆盖动作 |
| 0:55–1:35 | “申请一次推弹”→展示待确认→实体按住→中途松手 | AI申请与固件执行边界、有限次与可取消 |
| 1:35–2:00 | 再申请但不确认，或断网后查询/重连 | 明确拒绝、超时取消、不恢复旧动作 |
| 2:00–2:35 | 架构图、测试摘要、Git PR和v0 | 工程结构、异常处理和真实开发过程 |
| 2:35–3:00 | 展示价值假设与实际局限 | 已完成什么、实测什么、没有什么 |

优先保证声音清楚、设备与手部按键同时入镜、工具日志可辨。若语音延迟较长，保留原始连续录像，可另做有说明的剪辑版；不要剪出不存在的实时闭环。图像中遮盖Wi-Fi密码、账号token和协议凭据。

## 演示前检查

- 记录当前commit，准备已验证的整套镜像、烧录命令与数据线。
- 电池电量和电源规格已核对，独立断电开关可触及，车轮方向和机构行程已标定。
- 只使用验收通过的软弹和承接箱，首次空载演练，旁观者不在运动/飞轮范围。
- 确认2.4GHz网络与云端智能体，网页按实际IP打开，备用网络与受控演示空间准备好。
- 不临时升级依赖、改变模型或擦除NVS；故障时按分层说明排查。

## 交付视频

将真实录制文件上传GitHub仓库或该仓库Release资产，在 [demo目录](../demo/README.md) 记录标题、可访问位置、设备与固件版本、录制日期和是否剪辑。保持比赛要求的访问权限，使用另一会话检查评委能打开。当前目录只提供交付入口，不存在占位视频或伪造实机录像。
