# 底盘控制与无硬件验证

本模块对应第 4 步，分支为 fix/chassis-control。当前交付目标是完成固件逻辑与主机模拟验证；实车行驶、制动、语音链路和供电尚未验收。发射机构不在本模块范围内。

## 为什么修改

原实现为每条指令创建独立的延迟停车任务，旧任务到期会停止正在执行的新动作；情绪队列和阻塞舞蹈还能在停车之后继续产生移动。网页虽然发送重复心跳，设备端却丢弃相同方向和速度，没有实际的断联截止时间。现在只保留一份当前动作状态和一个周期执行任务。

## 模块与执行规则

- main/motor_control.h：不依赖 ESP-IDF 的状态机及共享默认参数。维护当前来源、方向、速度、截止时间和至多 8 步的序列。
- main/motor_control.cc：设备适配。处理任务创建、互斥、网络事件、LEDC 输出、配置加载和状态反馈。
- main/application.cc：网络断开/配网时立即请求停车；协议错误、音频通道关闭、协议重置、重启和进入固件更新流程时请求停车。聊天状态和云端情绪只更新显示。
- boards/intelligent-car/compact_wifi_board.cc：注册 MCP 工具，调用统一执行入口；不再用阻塞延迟执行舞蹈。
- main/web_server/：HTTP 参数校验、网页遥控心跳、配置与状态接口。

明确的移动指令按设备接收顺序覆盖，不再将低优先级动作排队等待。停止清除整个序列。新移动可以在停止后开始；停止不是永久禁行锁，也不是发射机构停止工具。保留的旧 C 兼容入口拒绝 priority < 1 的自动移动。

**定时动作：**语音工具、网页动作按钮和调试接口指定有限时长，执行器检查自身截止时间。网页租约不能提前截断已替换网页遥控的定时动作。调度延迟时跳过已过期步骤，不补跑旧动作。

**持续遥控：**网页拖动摇杆期间约每 200ms 发送一次指令；固件每收到一条有效指令就将租约延长到 750ms，即使方向、速度没变化也续期。停止、页面失焦、隐藏或触摸取消会结束拖动并请求停车；关闭页面尽力发送 keepalive 停止请求。请求失败后结束拖动，不持续重试运动指令。浏览器请求串行发送，保留最新待发指令，松手的停止不会被“正在请求中”丢弃。动作按钮先等待摇杆停车请求处理，再发送定时动作。

**执行器：**单个 FreeRTOS 任务按 20ms 周期检查截止时间。请求线程和执行器共用一把互斥锁，保护状态变更及 PWM 输出。750ms + 一个检查周期只是软件设计的正常调度目标，不能当作硬实时上限或机械制动距离；系统阻塞、网络缓冲和惯性仍需要实测。

**电机输出：**保持现有方向约定与引脚：1 右转、2 后退、3 左转、4 前进；GPIO 12/13/14/21 对应 LF/LB/RF/RB；LEDC timer 0、channel 0–3、20kHz、10 位。换向先将四路目标占空比归零，再设置目标方向，不使用独立 fade 任务。当前没有软启动与实车验证过的换向等待时间；电流与机械冲击须到货后验证。PWM 初始化或输出失败时取消动作、尽力拉低引脚并锁定故障到重启，禁止降级成不受速度参数约束的 GPIO 满速控制。未联网拒绝新移动；重连不恢复旧序列。

## 参数与兼容

| 项目 | 无历史 NVS 值时的初值 | 范围/说明 |
| --- | --- | --- |
| 默认速度 | 80% | 0–100%；0 表示停止；并非实测安全速度 |
| 前进 / 后退 | 1500ms | 100–10000ms |
| 左转 / 右转 | 600ms | 按时间转向，没有角度反馈 |
| 原 spin_around 工具 | 2500ms | 有限时长左转，不保证转满一圈 |
| quick_forward / quick_backward | 500ms | 使用当前保存的对应时长 |
| wiggle / dance | 600 / 1500ms | 分别拆为 2 / 4 步，每步至少 100ms，取整可能改变总时长 |
| 序列 | 至多 8 步 | 整个序列不超过 10000ms |

MCP 原工具名称保留。移动工具的 speed_percent、duration_ms 缺省均为 -1，表示调用时读取当前保存配置；它是参数缺省标记，不会输出负速度。明确时长必须为 100–10000ms。网页修改配置后，后续缺省 MCP 调用立即使用新值。速度为 0 直接停车。

有效的历史 NVS 值继续保留，不自动改成新初值；越界值仅在本次加载时回退并记录日志，不覆盖原始 NVS。网页配置 GET 返回完整配置；POST 允许局部数字字段更新，保留省略字段，拒绝错误类型和越界参数。旧表单接口保留。配置页面由字符串表单转换成数字 JSON 后提交。

self.motor.wake_up、happy 等既有情绪工具名称保留，但现在只更新显示；工具描述明确不会移动底盘。显式 wiggle、dance 仍会移动，执行前需要用户明确请求，并且可被新动作或停止取消。界面未加入新设计或控制鉴权：继续只在可信本地网络使用，多个控制端之间没有独占权，最后到达的有效指令覆盖前一条。

## 状态与 HTTP 接口

- POST /api/control：整数 direction 0–4、speed 0–100；持续遥控租约入口。POST /control 保留 direction=4,speed=80 格式。
- POST /api/motor/action：例如 {"action":"move_forward"}、{"action":"stop"}，使用当前配置。
- POST /api/debug/motor_test：可选整数 direction、speed、duration；缺省为前进及当前保存的速度、前进时长，仍使用统一定时执行器。
- GET /api/motor/status 或 MCP self.motor.get_status：返回 source、active、direction、speed_percent、remaining_ms、pending_steps、network_available、hardware_fault、feedback。
- GET/POST /api/config：配置读取与局部修改。

非法请求返回 HTTP 400，不改变当前动作；设备未联网、执行器创建失败或驱动故障时拒绝移动并返回 503。接受动作仍保留 status=ok，并提供 accepted=true、physical_completion_verified=false。MCP 移动失败抛出异常，由原有 MCP 层返回错误；成功只说明已接受，不再声称动作已经完成。

状态查询返回的是**软件命令与目标输出**，不是车轮的真实转速、位置、方向或到达确认。硬件故障可使目标输出未真正生效，必须同时看 hardware_fault。当前没有编码器、距离或命中传感器，也不提供导航、避障或瞄准能力。语音停车需要云端识别和工具调用，不是本地硬急停。

## 到货前如何检查

在仓库根目录运行：

    ./tools/test-chassis.sh
    CAR_TEST_SANITIZE=1 ./tools/test-chassis.sh
    ./tools/build.sh

需要主机 C/C++ 编译器、Node.js，以及已安装的 ESP-IDF；测试仅使用其现有 cJSON 源码，不安装依赖、不访问网络、不刷机。可通过 IDF_PATH、CC、CXX 指定本机工具。临时编译产物自动清理，不修改设备配置。

测试分四层：

1. 状态机：截止时间、动作替换、序列取消、相同心跳续期、控制来源切换、非法参数、迟到调度及长时间戳。
2. HTTP：直接编译生产 web_server.cc，用 HTTP/设备替身验证分段接收、无效请求、旧接口、调试动作覆盖、状态及局部配置；不会连接真实 HTTP 服务。
3. 设备适配：直接编译生产 motor_control.cc，用主机替身替代 FreeRTOS、LEDC、GPIO、时钟和 NVS。验证方向映射、单执行器、断网清除、任务创建失败、PWM 初始化/写入/停车失败、故障锁定、历史配置回退。替身不模拟电气或真实 RTOS 调度。
4. 网页：Node VM 执行固件内嵌的真实脚本，DOM 与 fetch 为替身。验证松手停车排队、相同心跳、按钮顺序、失焦/隐藏/触摸取消处理、请求失败及配置数字类型。不是浏览器实机端到端验收。

硬件到货后至少检查：车轮悬空时的四向映射、低速度起转与换向电流、停止/断网后的真实输出与滑行、长按摇杆/松手/切后台、语音新动作覆盖旧动作、舞蹈途中停止不再移动、屏幕情绪不转轮。测试断网和驱动异常前先具备直接切断电机动力的方法；保持发射机构未供电。
