# 架构设计与模块规格

## 总体结构

~~~mermaid
flowchart LR
    U[用户语音] --> A[麦克风与音频服务]
    A <--> P[MQTT / WebSocket 协议]
    P <--> C[灵矽智能体与语音服务]
    C --> M[MCP 工具调用]
    M --> B[板级工具与参数检查]
    B --> D[底盘执行器]
    B --> T[炮塔申请与执行器]
    H[局域网网页] --> D
    K[独立实体确认按钮] --> T
    D --> W[四路电机 PWM]
    T --> F[飞轮 GPIO 与舵机 PWM]
    S[停止 / 断网 / 生命周期事件] --> D
    S --> T
~~~

部署方式是 ESP32-S3 运行固件，云端使用灵矽提供的语音/智能体链路；本项目没有额外必须部署的自建后端。主机 C++ 与 Node 测试在开发电脑运行，不上传真实音频、不冒充设备激活。局域网网页不负责模型推理。

## 模块规格与分工

当前为单人项目，所有模块的实现、核对和验收责任由参赛者承担；以下是职责划分，不代表多人协作。

| 模块与源码 | 输入 | 输出 / 职责 | 失败处理 |
| --- | --- | --- | --- |
| boards/intelligent-car/config.h、compact_wifi_board.cc | 板型、接线、按钮、MCP参数 | 外设初始化、工具注册、实体确认事件 | 配置或初始化错误需排查，不猜测接线 |
| application.cc/.h | 网络事件、对话状态、生命周期 | 调度主线程、连接协议、联动停车 | 协议错误、重置、升级/重启入口请求停车 |
| audio/ | 麦克风采样、下行音频 | 处理/编码/解码、唤醒和播放 | 通过音频与协议日志分层检查 |
| ota.cc、protocols/ | 设备身份、云端连接配置 | OTA/激活、MQTT或WebSocket及音频/MCP消息 | 激活失败保留可诊断信息，不把GET健康检查当握手通过 |
| mcp_server.cc | 云端工具名、JSON参数 | 类型/范围检查、工具结果或ReplyError | 不存在工具或动作拒绝如实返回错误 |
| motor_control.h | 方向、速度、时长、序列、时间 | 纯状态机：替换、取消、租约、过期步骤跳过 | 非法输入拒绝，停止清空序列 |
| motor_control.cc | 状态机、网络状态、NVS配置 | 单任务20ms轮询、四路PWM、目标状态JSON | 驱动故障锁定到重启，尽力关断，不退化成满速GPIO |
| turret_control.h | 申请、实体确认、时间、取消 | 待确认、预转、推弹、回位的有限状态机 | 超时或严重迟到取消，不补跑旧推弹 |
| turret_controller.cc/.h | 配置、实体按钮、网络 | 单任务20ms轮询、飞轮/舵机、状态快照 | 默认禁用，错误锁定、关闭输出、禁止自动恢复 |
| web_server/ | 局域网HTTP与按钮/触摸事件 | 调试网页、底盘命令、参数持久化 | 请求校验、客户端超时、心跳租约和显式停止 |
| settings.cc | 配置键与值 | NVS读写，保留历史有效值 | 非法历史值回退但不静默覆盖原始数据 |

路径均相对于 firmware/main。第三方组件、来源与许可证见 [来源说明](../CODEBASE.md) 和 [许可声明](../THIRD_PARTY_NOTICES.md)。

## 关键时序与并发

语音动作：识别用户意图 → 云端 MCP → 板级工具取当前参数 → Application → 状态机 → 同一把模块锁内更新输出 → 返回接受/拒绝。工具接受不是实物完成。底盘和炮塔各有单个执行任务，不为每条命令创建无法取消的延迟任务。

底盘支持 timed 与 web 两种来源，按到达顺序覆盖；网页每200ms发送心跳，固件750ms租约到期停车，浏览器500ms请求超时。网页串行发送并保留最新待发命令，停止和新一代输入会清除旧操作。

炮塔流程：prepare(1..3) → awaiting_confirmation（最多10秒）→ 申请之后的独立按下与长按 → spinning → pushing → recovering → disarmed。持续按住只能完成本次有限申请。松手回调取消，执行器还直接检查按钮电平；远程不存在确认入口。

停止先分别取得模块锁，不嵌套持有底盘和炮塔锁；旧停车入口同时取消炮塔，避免新接口出现旁路。断网同步撤销输出，重连只恢复接收新命令，不恢复旧动作。状态查询不等于传感器反馈；炮塔查询本身不推进推弹动作。

## 硬件资源与配置

| 资源 | 用途 |
| --- | --- |
| LEDC timer0、channel0–3、20kHz / 10bit | 底盘 LF/LB/RF/RB |
| LEDC timer2、channel4–5、50Hz / 14bit | 推弹 / 可选俯仰舵机 |
| 数字GPIO | 飞轮驱动控制、按钮和灯；GPIO不直接供电给电机 |
| I2C / I2S | OLED / 麦克风与扬声器，接线见硬件说明 |
| NVS | Wi-Fi、协议连接设置、底盘动作参数等；本机生成配置不提交 |

舵机脉宽、预转和回位时长是待标定软件初值。引脚和机构不兼容时必须拒绝启动或进行适配，不能为了演示跳过校验。

## 信任边界和限制

云端决定语义和工具参数，固件决定参数是否合法、能否执行和何时取消。提示词不是唯一动作约束。当前无编码器、距离、转速、弹丸或命中传感器，也没有公共互联网远控服务。网页应只在受控局域网使用，不能视作公网鉴权系统。

软件关断存在调度延迟，机械仍有惯性；独立硬件断电不由语音保证。模拟测试覆盖逻辑和驱动调用，无法证明真实电气行为。实际云端密钥和Wi-Fi密码不进入源码/PR/演示日志。

## 验证策略

主机直接编译生产状态机、HTTP和设备适配；浏览器测试执行生产页面脚本；驱动替身注入GPIO、LEDC、任务创建失败及时间推进，使用ASan/UBSan检查。ESP-IDF完整构建检查真实芯片头文件、资源生成、链接和分区大小。最后必须进行板级、音频、云端、底盘和机构分层实机验收，见 [验收矩阵](acceptance.md)。
