# 硬件到货前准备审计

目标是把已知软件准备完成，将到货后的常规工作收敛为接线、配置、标定和验收。当前没有实物型号或真实云端设备响应，不能承诺任何器件都无需修改代码。

## 已准备的交付物

## 现在仍可由参赛者完成的非代码工作

1. 按[物料兼容条件](hardware.md)确定采购型号，取得原理图、额定电压/电流、驱动真值表和机械行程资料。未知型号无法提前验证适配。
2. 登录灵矽控制台准备智能体、权限/额度及[分阶段提示词](agent-prompt.md)。账号操作尚无完成证据；设备MAC与绑定必须等实物。
3. 准备2.4GHz网络、数据线、独立动力开关、万用表、固定结构与软弹承接箱，确认比赛GitHub访问权限。
4. 预演[演示脚本](demo.md)，按[验收矩阵](acceptance.md)记录真实结果；不要用主机模拟代替实机视频。

## 到货后的顺序

不接动力核对型号/接线 → 烧录与基础外设 → Wi-Fi和只读局域网接口 → 云端身份/协议/语音/MCP → 悬空底盘 → 无弹机构与实体确认 → 参数标定 → 异常演练 → 软弹承接箱验证 → 真实录像与GitHub交付。

炮塔保持默认禁用，确认实物后才配置启用。常规参数调整走[配置工具](build.md#硬件参数配置与完整检查)，重新编译烧录；若实物使用不同驱动、机构或云端返回不兼容协议，应补适配并走PR，不能为达到“零代码改动”绕开校验。
